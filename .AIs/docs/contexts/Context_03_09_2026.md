# Contexto Diário — 03/09/2026

## Resumo

A feature de diagnóstico do veículo foi retirada do escopo planejado porque não
será entregue no prazo atual. Foram removidas a tela, os atalhos, a API prevista
e a entidade proposta para snapshots de diagnóstico.

Também foi criado um roadmap exclusivo para Backend e MQTT. O documento trata o
ESP32 como produtor das medições e concentra o escopo na recepção, validação,
persistência, tratamento, análise e disponibilização segura dos dados para
mobile e desktop.

Após revisão de prioridade, o roadmap passou a entregar primeiro todas as APIs
dos aplicativos usando fixtures e dados sintéticos. A integração MQTT ficou
condicionada a um marco de prontidão do ESP32 ou de um simulador aprovado, para
que nenhuma fase seja considerada testada sem uma fonte executável de mensagens.

O desenvolvimento foi iniciado pela Fase 0. O baseline confirmou build e 23
testes preexistentes e identificou 48 arquivos vazios na árvore canônica. A
configuração do pnpm foi corrigida, o lint foi instalado e aprovado, o possível
handle aberto do Jest foi descartado e o Prisma Client foi gerado em ambiente
isolado com URL sintética. `prisma.config.ts` e `postinstall` tornaram a geração
reproduzível sem carregamento implícito de `.env`. Nenhuma API de negócio foi
iniciada.

O envelope comum de respostas criado antes da conclusão da Fase 0 foi revertido,
incluindo seu teste, para restabelecer a ordem definida no roadmap.

Ficou definido que desktop e mobile possuem as mesmas features e consumirão os
mesmos contratos. Portanto, não existe pendência de levantamento exclusivo do
desktop antes da Fase 1.

## Incidente operacional

Uma primeira tentativa de isolar a geração do Prisma dentro do repositório fez
o CLI localizar e carregar automaticamente o `.env` da raiz, sem imprimir seus
valores, antes de falhar. A tentativa foi interrompida e substituída por um
ambiente temporário fora do repositório. Nenhum conteúdo ou segredo foi exibido,
alterado ou versionado.
