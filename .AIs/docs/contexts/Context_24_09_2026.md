## 1. O que foi implementado (sessão IA, com aprovação do programador)
Problema: imagem do app abria no localhost, mas o iPhone via Expo Go não conectava.
Causas raiz encontradas:
1. `docker-compose.yml` mapeava `8080:8081` — o QR anunciava a porta 8081, mas o
   host escutava na 8080 (só a versão web em `localhost:8080` funcionava).
2. Expo iniciava em modo localhost (`Waiting on http://localhost:8081`) — QR
   apontava para localhost, inalcançável pelo celular.
3. Trava de conta: celular logado como `gabrieldomingues` e CLI deslogado —
   Expo Go recusava abrir (`Run "npx expo login"...`).

Arquivos alterados pela IA nesta sessão:
- `docker-compose.yml` (serviço `mobile`): portas `8081:8081` + `19000–19002`,
  `stdin_open: true` + `tty: true`, env `EXPO_TOKEN: ${EXPO_TOKEN:-}`.
- `docker/Dockerfile.mobile`: `EXPOSE 8081 19000 19001 19002`,
  `ENV EXPO_DEVTOOLS_LISTEN_ADDRESS=0.0.0.0`,
  CMD `pnpm --filter @vers/mobile exec expo start --lan --port 8081`.
Validação: `docker logs vers-mobile` mostra QR + `Metro: exp://192.168.0.106:8081`;
`expo whoami` responde o usuário do Expo. Web em `http://localhost:8081`.

## 3. Runbook — subir o mobile (PC atual ou outro)
Uso diário:
1. Docker Desktop aberto (`Engine running`).
2. `cd` na raiz do projeto → `docker compose up -d mobile`.
3. Se Wi-Fi/rede mudou: `ipconfig`, atualizar `EXPO_HOST` no `.env`
   (feito pelo programador, nunca pela IA) e repetir o passo 2.
4. `docker logs -f vers-mobile` → escanear QR no Expo Go (mesmo Wi-Fi
   192.168.0.x) ou "Enter URL manually" → `exp://<IP>:8081`.
5. Parar: `docker compose stop mobile`. Ver estado: `docker ps`.
Primeira vez em outro PC: instalar Docker Desktop (WSL2), copiar projeto, criar
`.env` do `.env.example` (`EXPO_HOST`, `EXPO_API_URL`, `EXPO_WS_URL` com o IP
local + `EXPO_TOKEN` do expo.dev), `docker compose up -d --build mobile`,
validar com `docker exec vers-mobile pnpm --filter @vers/mobile exec expo whoami`.
Para testar API junto: `docker compose up -d backend redis`.
